# slowyshop

MVP магазина цифровых товаров с каталогом, резервированием отдельных единиц, защищенной выдачей, личным кабинетом и админкой.

## Запуск локально

```bash
npm start
```

Откройте `http://localhost:3000`.

При первом локальном запуске администратор создается автоматически. Если `ADMIN_PASSWORD` не задан, пароль выводится в консоль. Для предсказуемого входа скопируйте `.env.example` в `.env` и задайте пароль длиной от 12 символов.

```text
ADMIN_EMAIL=admin@slowy.local
ADMIN_PASSWORD=your-strong-password
```

Локально по умолчанию включен `PAYMENT_MODE=demo`: он позволяет пройти сценарий оплаты без реального списания денег. Demo-товары создаются из старого числового остатка при первом запуске. Перед реальными продажами загрузите собственные аккаунты через админку и отключите demo-инвентарь.

## Модель продажи

1. Администратор создает товар.
2. В админке импортируется партия строк в формате `логин|пароль|дополнительные данные`.
3. Секреты шифруются AES-256-GCM и не возвращаются в админский API.
4. При создании заказа конкретные единицы товара резервируются на `RESERVATION_MINUTES`.
5. Товар переводится в `sold` только после demo-подтверждения или подтвержденного webhook YooKassa.
6. Покупатель открывает данные только из личного кабинета после оплаты.

Продажа взломанных, украденных или запрещенных правилами сервиса аккаунтов недопустима. Проверяйте происхождение товара и правила каждой площадки.

## Реальные платежи

Для YooKassa задайте в `.env`:

```text
NODE_ENV=production
APP_ORIGIN=https://your-domain.example
PAYMENT_MODE=yookassa
YOOKASSA_SHOP_ID=...
YOOKASSA_SECRET_KEY=...
```

В кабинете YooKassa укажите webhook:

```text
POST https://your-domain.example/api/payments/yookassa/webhook
```

Провайдер должен быть настроен до публикации магазина. Webhook повторно проверяет платеж через API YooKassa, сверяет валюту и сумму, поэтому клиентский redirect не считается оплатой.

## Production checklist

- Использовать HTTPS и `COOKIE_SECURE=true`.
- Задать стабильный случайный `ENCRYPTION_KEY` длиной минимум 32 символа. Не менять его после импорта инвентаря.
- Задать сильные `ADMIN_PASSWORD` и `ADMIN_EMAIL`.
- В production значение `ADMIN_PASSWORD` синхронизируется с существующим администратором при старте.
- Установить `SEED_DEMO_INVENTORY=false`.
- Не использовать `PAYMENT_MODE=demo` для реальных продаж.
- Настроить SMTP для подтверждения email и уведомлений.
- Для production SMTP обязателен: код не сохраняется и регистрация не подтверждается, если письмо не отправлено.
- Ограничить права на каталог `data`, делать резервные копии и не публиковать `data/db.json` веб-сервером.
- Разместить оферту, политику конфиденциальности, правила гарантии и возврата, реквизиты продавца.
- Проверить юридическую возможность продавать каждый тип аккаунтов.

## Бесплатная публикация через GitHub и Cloudflare Workers + D1

GitHub хранит исходный код, Cloudflare Worker запускает API, а D1 хранит состояние магазина. Worker не засыпает как бесплатный Render Web Service. Бесплатный D1 имеет лимит 500 МБ на базу, поэтому этот вариант подходит для небольшого магазина и тестового запуска, но не заменяет полноценную production-базу с резервными копиями.

1. Установите Node.js и выполните `npm install`.
2. Авторизуйте Wrangler: `npx wrangler login`.
3. Создайте D1: `npx wrangler d1 create slowyshop`.
4. Вставьте выданный `database_id` в `wrangler.jsonc` вместо `REPLACE_WITH_D1_DATABASE_ID`.
5. Примените схему: `npx wrangler d1 migrations apply slowyshop --remote`.
6. Добавьте секреты командами `npx wrangler secret put ADMIN_PASSWORD`, `ENCRYPTION_KEY`, `RESEND_API_KEY`, `YOOKASSA_SHOP_ID` и `YOOKASSA_SECRET_KEY`.
7. Перед деплоем добавьте секрет `APP_ORIGIN` через `npx wrangler secret put APP_ORIGIN` со значением `https://slowy.lol`, а email задайте секретом `EMAIL_FROM`.
8. Опубликуйте: `npm run cf:deploy`.
9. Конфигурация уже содержит Custom Domain `slowy.lol`. SSL и DNS для активной зоны Cloudflare выдаются автоматически после `npm run cf:deploy`.
10. В YooKassa укажите webhook `https://slowy.lol/api/payments/yookassa/webhook`.
11. После первого запуска войдите в админку и импортируйте проверенный инвентарь. Локальная база не переносится автоматически, чтобы не публиковать персональные данные и секреты.

Для Resend нужен API key и подтвержденный адрес отправителя. SMTP напрямую из Worker не используется, потому что Worker не открывает обычные SMTP-порты.

## Telegram-бот заявок

Бот принимает заявки на фридеп, редеп с возвращением баланса и деп 50/50. Он проверяет только HTTPS-домен и формат публичной ссылки на профиль LOLZ, а сам профиль проверяет оператор вручную через админку. Бот не должен получать пароли, cookies, коды подтверждения, платежные данные или доступы к аккаунтам.

### Локальный запуск

1. Создайте бота через `@BotFather` и скопируйте токен в `.env`.
2. Запустите приложение с `TELEGRAM_MODE=polling`.
3. Напишите боту `/id`, чтобы узнать свой числовой chat ID.
4. Укажите этот ID в `TELEGRAM_ADMIN_CHAT_IDS`, перезапустите приложение. Если уведомления будут приходить в группу, дополнительно укажите личный числовой ID администратора в `TELEGRAM_ADMIN_USER_IDS`, чтобы он мог нажимать кнопки проверки.
5. Откройте бота и отправьте `/start`.

Polling предназначен для локальной разработки. Одновременно использовать polling и webhook нельзя.

### Production webhook

Для публичного HTTPS-домена задайте:

```text
TELEGRAM_MODE=webhook
TELEGRAM_WEBHOOK_URL=https://your-domain.example/api/telegram/webhook
TELEGRAM_WEBHOOK_SECRET=случайная-строка-без-пробелов
TELEGRAM_ADMIN_CHAT_IDS=123456789
```

После запуска приложение само зарегистрирует webhook через Telegram Bot API. Запросы дополнительно проверяются заголовком `X-Telegram-Bot-Api-Secret-Token`. Обновления дедуплицируются по `update_id` и сохраняются в той же JSON-базе, что и админка.

### Сценарий заявки

1. Пользователь нажимает «Подать заявку».
2. Бот принимает публичную HTTPS-ссылку на профиль LOLZ и проверяет домен/путь.
3. Ссылка появляется в админке со статусом «проверка профиля», а администратор вручную нажимает «Ссылка проверена» или «Отклонить».
4. После подтверждения пользователь выбирает «Фридеп», «Редеп с возвратом баланса» или «Деп 50/50».
5. Пользователь добавляет комментарий либо пропускает его.
6. Заявка появляется в админке в разделе «Обращения», а администраторы получают уведомление в Telegram.
7. Ответ администратора и изменение статуса доставляются пользователю в Telegram.

Заявки используют существующую модель обращений (`tickets`) с `source=telegram`; отдельный процесс для бота не нужен.

## API для интеграции

- `GET /api/products` — активный каталог.
- `POST /api/orders` — создать заказ и резерв.
- `POST /api/payments/demo/confirm` — только demo-оплата.
- `POST /api/payments/yookassa/webhook` — webhook реальной оплаты.
- `GET /api/orders` — заказы покупателя.
- `GET /api/orders/:id/delivery` — защищенная выдача.
- `POST /api/tickets` — обращение в поддержку.
- `POST /api/tickets/:id/reply` — ответ покупателя в существующем обращении.
- `/api/admin/*` — операции администратора.

## Документы магазина

Ссылки `Оферта`, `Конфиденциальность` и `Правила возврата` открывают документы в интерфейсе. Текст в оферте содержит место для реквизитов продавца: перед запуском замените шаблон на реальные данные и проверьте документы с юристом для вашей юрисдикции и типов товаров.

Данные хранятся в JSON-файле для простого MVP. Для высокой нагрузки и нескольких процессов замените хранилище на SQLite/PostgreSQL с транзакциями и миграциями.
